## 계산기 마감 정리 — 타이포 스케일·숫자 고정폭·상태 피드백·면 분리

"토스 보면 우리는 디테일이 없어 보인다"는 지적을 실측으로 분해한 뒤(아래 수치), 팀이 정리한
`docs/reference-rules.md` 규칙에 맞춰 손봤다. 계산 로직은 건드리지 않았다(CSS만).

### 무엇이 문제였나 (실측)
- 렌더된 글자의 **대부분이 12px**(64회). 크기는 10종인데 위계는 사실상 없음 — 큰 숫자 하나만 튐.
- 텍스트 77곳이 `line-height:normal` — 줄간격을 브라우저에 맡겨 카드마다 리듬이 다름.
- 히어로 숫자에 고정폭 미적용 → 슬라이더를 한 칸 움직일 때마다 폭이 126.7~129.5px로 출렁임.
- 클릭 가능한 10개 중 **7개가 transition 0초**, focus 스타일은 CSS 전체에 2개.
- 탭 28px·초기화 28px·슬라이더 16px — 40px 미만 클릭 대상.
- 결과 존이 **카드 5장**으로 쪼개져 각자 그림자+20px 패딩(패딩만 세로 200px) → "레이어가 떠 있고
  빈 공간이 많다"는 인상의 실제 원인.

### 무엇을 했나
- **타이포 6단 스케일**(12/14/17/22/28/36 + 줄간격 16/20/24/28/34/44)로 스냅. 인접 배율 1.2~1.3.
- **컬럼을 하나의 패널로**: 카드별 그림자·radius를 없애고 hairline border로 구분(규칙2).
- **숫자 고정폭**(tabular-nums)을 히어로·KPI·시장통계·합계까지 확대.
- **상태 피드백**: hover/active(scale .97)/focus-visible 링, 탭·초기화 36px, 슬라이더 28px.

## 계산기 후속 3건 + 시장 근거 문구 제거

- **빈 공간**: 시장비교 카드를 결과 패널 안 마지막 섹션으로 옮기고, 입력 패널은
  `position:sticky`로 스크롤을 따라오게 했다. 전엔 입력(825px)이 결과(975px)보다 짧아
  오른쪽 아래가 비었고, 시장 카드는 전체폭으로 따로 떨어져 있었다.
  이제 결과 1,385px / 입력 827px(sticky)로, 스크롤 끝까지 양쪽이 채워진다.
- **4px 리듬**: margin/padding/gap 값을 4의 배수로 스냅(6→8 20회, 14→16 13회, 10→8 6회 등
  총 53회). 0·1·2px 헤어라인급은 유지.
- **숫자 롤링**: 히어로 월 순수익이 값 변화 시 260ms easeOutCubic으로 굴러간다.
  `prefers-reduced-motion: reduce`면 즉시 반영.
- **시장 근거 문구 제거**(사용자 요청): "N건 기준(삼삼×네이버 매칭)|예약률 20% 이상|크롤 기준"
  삭제. 다만 표본 부족으로 전국 수치를 대신 보여줄 때의 안내는 남겼다 — 안 남기면 라벨(인천 원룸)과
  숫자(전국)가 어긋난다.

검증: 계산 5개 시나리오 일치, 롤링 동작 확인(+44 → 중간 +18 → 최종 +6), 모바일 가로 스크롤 없음,
페이지 높이 1,900 → 1,864px.
