## 크롤 대상 지역 확장: 부산·천안 (+ 수도권 필터 버그 2건)

사용자 요청으로 삼삼·네이버 크롤에 **부산 전역과 천안시**를 추가했다. 지역 조건이 코드
여러 곳에 하드코딩돼 있어(수도권 시도명 3개) 먼저 한 곳으로 모았다.

- **`common/target_regions.py` 신설** — 크롤·노출 대상 지역의 단일 출처.
  `METRO_PREFIX`(서울/경기/인천 접두) + `EXTRA_REGIONS`(기본 `부산,천안시`,
  env `RENDIT_EXTRA_REGIONS`로 조정). `in_target()` / `sql_where()` /
  `sql_literal()`(뷰 정의용) / `short()` 제공.
  - 접두·부분일치를 쓰는 이유: **시도 표기가 소스마다 다르다.** 삼삼은 `부산광역시`,
    네이버는 `부산시`. 천안은 시도가 아니라 시군구라 `'시도 시군구'` 문자열 부분일치.

## 크롤러 exe: 전국 지역 선택 (사용자 요청 — "원하는 만큼 크롤링")

- 삼삼 탭에 **지역 선택(전국 17개 시도) + 시군구 좁히기** 추가. 네이버 탭은 이미 전국
  시도 선택이 있었다. 버튼: 전국 전체 / 수도권만 / 전체 해제.
- 이를 위해 `target_regions`에 **통째 지정 모드** 신설: `RENDIT_TARGET_REGIONS`
  (수도권 자동 포함 없음, `*`/`ALL`/`전국` = 필터 없음). 기존 `RENDIT_EXTRA_REGIONS`는
  "수도권에 더하기" 의미 유지.
  - 광주는 토큰을 `광주광역`으로 — `경기도 광주시`와 섞이지 않게.
  - 지역 미선택 시 `sql_where()`가 `FALSE`를 돌려주도록(전체 노출 사고 방지).
- exe가 서버 모드로 네이버를 돌면 `nl_live` 뷰를 갱신하는데, 여기서 지역을 통째 지정하면
  **사이트 노출 범위가 exe 선택으로 좁아지는 사고**가 난다 → 뷰 갱신 단계에서는
  운영 기본 범위 + 이번에 크롤한 시도를 **더하는** 방식(EXTRA)으로 처리.
- `target_regions`는 import 시점에 env를 읽으므로 실행 전 `sys.modules`에서 제거(캐시 무효화).
- 빌드·배포: PyInstaller onefile 59.4MB, frozen `--selftest` PASS, 바탕화면 교체
  (`rendit통합크롤러.exe` / `_새버전.exe` 둘 다 최신 빌드로 덮어씀. 07-30자 .zip은 구버전).
