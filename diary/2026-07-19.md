# 2026-07-19

## Oracle Cloud 프로덕션 배포 — https://rendits.duckdns.org (웹 세션)

"서버가 전반적으로 느리다" 진단(7/17)에서 출발: 주범은 Vercel(미국 iad1)↔Supabase(서울) 태평양
왕복(페이지 ~1초) + 서버리스 콜드스타트. kv_cache precompute(#224)로 20초 재계산은 없앴지만
왕복 자체는 리전 문제 → 팀원의 Oracle Cloud Free VM으로 이전.

### 서버 스펙 (팀원 제공, ubuntu@158.179.170.9)
- **ap-chuncheon-1(춘천!)** · VM.Standard.A1.Flex — ARM Ampere 4코어(Neoverse-N1)·**24GB RAM**·194GB
- Supabase(서울) TCP 왕복 **54ms** (Vercel 대비 ~20배 단축). 기존 팀원 서비스 starec2(포트 13999/42257)
  가동 중 — 안 건드림. iptables는 비어있고 정책 ACCEPT → 방화벽은 OCI 보안목록(콘솔)만.

### 배포 과정
1. paramiko(SSH)로 원격 작업. Docker 29.6.2 설치(get.docker.com), STA clone, .env SFTP 전송.
2. `docker compose up -d --build` — ARM64 빌드(python:3.11-slim 멀티아키 확인). 내부 응답 **3.5ms**.
3. OCI 보안목록: 팀원에게 최소개방 원칙 메시지 전달(80/443만, 예비포트는 안티패턴이라 제외,
   5432 금지, SSH 비번노출 경고 포함). 개방 후 80으로 재매핑(docker-compose.override.yml,
   `ports: !override`).
4. **Postgres 17 컨테이너**(pg, 도커 네트워크 내부 전용·포트 미노출·비번은 서버 .env에만) 가동.
   Supabase→로컬 복사는 가드레일로 사용자 승인 대기 중. (첫 시도 실패 원인: `source <()`는 bash 전용
   — sh에선 빈 값. `$(grep|cut)` 방식으로 해결.)
5. **DuckDNS**: 사용자가 rendits.duckdns.org 생성 → 스크린샷의 토큰으로 API IP 설정. DNS 확인.
6. **Caddy 2**(caddy:2-alpine) 리버스프록시: 처음엔 http 직접 서빙(443 미개방 대비)으로 올렸는데
   Let's Encrypt가 tls-alpn-01(443)로 검증 성공 → 443도 열려 있었음. 인증서 자동 발급 확인 후
   표준 구성 전환: https 서비스 + http/IP → https 리다이렉트(308/301).

### 결과
- **https://rendits.duckdns.org — 35~55ms** (Vercel 913~1134ms 대비 ~25배). 콜드스타트 0.
- 로그인·대시보드(스팟 16카드)·profit/map_all API 전부 정상, JS에러 0.
- restart:unless-stopped — 재부팅·크래시 자동 복구. Vercel은 백업으로 유지(main push 자동배포 계속).
- 접속정보는 C:/STA/.env(ORACLE_HOST/USER/PASSWORD, RENDIT_DOMAIN)에 저장.
