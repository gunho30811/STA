### 4. 로컬 크롤 GUI (.exe) — gui/rendit_crawler.py + common/local_db.py
- 사용자 요청: 버튼 누르면 창 뜨고 크롤하는 프로그램. 접속정보는 입력창에 기입. DB 대신 로컬 폴더 누적도 선택.
- tkinter GUI: 삼삼 계정 2개·매물종류 체크박스·테스트(50건)·실시간 로그. 입력값은 옆
  `rendit_crawler_config.json`에 저장. 파이프라인(crawler→snapshot→export)을 in-process 호출.
- **저장 위치 선택**:
  - Supabase(DB URL) 또는 **로컬 폴더(SQLite)**. 로컬은 `common/local_db.py`를 `sys.modules['db']`로
    주입해 크롤러가 그대로 선택 폴더의 `samsam.db`에 upsert 누적 + jsonl도 그 폴더에 export.
  - local_db는 samsam 크롤러의 PG 방언을 SQLite로 흡수: `%s`→`?`, `ON CONFLICT ... EXCLUDED`(SQLite 지원),
    `ALTER ... ADD COLUMN IF NOT EXISTS`(중복 무시), 행은 `r[0]`/`r['col']`/`r.get()` 모두 지원.
  - 오프라인 단위검증 통과: init→ALTER→upsert(%s+ON CONFLICT)→SELECT→snapshot→export, 폴더에 db+jsonl 생성.
- PyInstaller onefile+windowed 빌드(~60MB). 크로미움은 번들 안 하고 PC 설치본 사용(다른 PC는 첫 실행 시
  `playwright install chromium`). 프로즌 exe에서 `--selftest`(모듈/경로/의존성) PASS.
  ※ 실제 [크롤 시작] 클릭(크롬 로그인) 런타임은 GUI라 미검증 — 로컬 크롤과 동일 코드경로.
- 배포물은 bytes 커서 채팅 첨부 불가 → 바탕화면 `삼삼크롤러.exe`로 전달.

## 수익성 순위: 종류별 매칭 확장 + /samsam 모바일 개선

- **문제**: 수익성 순위(net_profit)가 97% 오피스텔 — `build_integrated`가 네이버를 OPST로만 제한했기 때문.
- **종류별 매칭**: `SAM_TO_NAV`(오피스텔↔OPST/아파트↔APT/연립빌라↔VL/단독주택↔DDDGG/원룸건물↔OR/
  상가주택↔SG·DDDGG). `load_nav` 전유형 로드 + `strict_match`가 같은 유형끼리만(위치+면적±15%+층±3) 매칭.
  결과: 4,764→ 오피 3,834·원룸 527·단독 147·아파트 104·연립 90·상가 62(6종 전부).
- **DB→DB**: `build_integrated`가 끝에 `export_net_profit`까지 호출해 net_profit 테이블 직접 적재
  (CSV는 레거시 백업, 웹은 테이블만 읽음). `--no-db`로 스킵 가능.
- **/samsam 모바일**: 표 첫 컬럼(이름) `position:sticky left` — 가로로 밀어도 어느 건물인지 유지(경계 그림자).
  시/도 칩·필터 컴팩트화, `.hint` 인라인 입력 탭 쉽게 확대. 모바일(390px) 스크린샷으로 검증.
  frontend/dist/samsam 재빌드 커밋.
- **/samsam 건물인기 모바일 카드+모달**: 가로 슬라이딩이 여전히 불편하다는 피드백 → 모바일에선 표 대신
  카드 리스트(건물명·예약률 + 📍시군구 동·유형·평·매물수)로, **행 탭 시 전체 상세 모달**(예약률 1/2/3달·
  최저최고·평·역·매물/매칭수·주당·월순수익·손익분기점·부동산 전화/링크). PC는 기존 표 유지(.desk-only/.mob-only).
  모바일 390px 스크린샷으로 카드·모달 검증.
- **프로핏 매칭 완화 + 미매칭 노출**: (요청) 좌표 매칭 반경 15m→200m(격자 ±2칸), 네이버 미매칭
  수도권 매물도 삼삼 데이터만이라도 표시(비교지표는 공란). build_rows 리팩터(삼삼 공통 계산 분리 +
  nav_fields 조건부), net='' 는 정렬 뒤로, export _num이 빈값→None 처리라 안전.
  결과: net_profit 4,782 → 17,219(매칭 8,371[200m로 4,782에서 증가] + 미매칭 8,848). 예약률20%↑ 뷰 2,841→8,660.
  build→export 로 net_profit 테이블 직접 갱신. profit_app._CACHE 는 프로세스당 1회 로드라
  Vercel 재배포(코드 push) 시 새 인스턴스가 갱신본을 읽음.
- **웹 캐시 stale 근본 수정(중요)**: profit_app `_CACHE`·samsam_app `_LC/_IDX/_MC` 가 프로세스당 1회

## 지도 성능 개선 — "왜 이렇게 느려?" 근본 수정

- 수정: `/api/map_all`(전 렌트 콤팩트 배열+전 동 원, 서버 5분 캐시·2.3MB) **최초 1회 로드** →

  직접(+`ix_nl_latlng`)·정렬 제거로 4.2s→0.3s. `ix_listings_latlon`도 생성(nl_live용). 클러스터
  animate:false. 오래된 응답 시퀀스 가드.
- 실측: 초기 1.3~2.7s(22,294개), 팬 API 0회(즉각), 네이버 fetch 0.35s. 남은 비용은 줌 시
  22k 재클러스터 연산(실브라우저 ~1s 수준)뿐.
