## 네이버 크롤 확장: 거래유형·다지역 + 로컬 GUI(.exe) + 주간크롤 7종 (feature/realtime-listings-view)

전날(7/15) 수도권 7종 월세 재크롤 + 사이트 실시간 뷰(nl_live/nl_base)에 이어, 아래를 추가.

### crawler.py 파라미터화 (거래유형·다지역)

- `--trade-types`(B2월세/B1전세/A1매매, 기본 B2), `--sidos`(수도권 복수 정확매칭) 추가.
  `articles_page`/`crawl_dong`에 trade_type 반영, 진행상태 키에 거래유형 포함(월세는 기존 키 유지=주간크롤 재개 호환).
  전세(B1)·매매(A1) 라이브 데이터 반환 검증(전세 65억/25억, 매매 48억/60억 등).

### 사이트 보호: 뷰에 월세 필터

- `create_live_view.py`: nl_live/nl_base WHERE에 `tradetype='월세'` 추가 — 로컬/Supabase로 전세·매매를
  긁어 넣어도 사이트(월세 전용)는 영향 없음.

### 주간 자동크롤 갱신 (crawl.yml)

- 목록 크롤 7종(상가·전원주택 포함)으로 확대. **crawl_state 리셋 스텝 추가** — 안 그러면 done이 남아
  전량 스킵돼 주간 갱신이 안 되고, 7일 신선도 필터 때문에 사이트가 비게 됨.
- 목록 후 `create_live_view.py`(뷰·인덱스 갱신+VACUUM ANALYZE) 스텝, 상세는 `--sidos` 수도권 명시,
  timeout 300→360분.

### 네이버 로컬 크롤 GUI (.exe) — 삼삼과 별개 독립 프로그램

- `gui/naver_crawler.py` + `common/naver_local_db.py`(네이버 테이블 SQLite 스키마).
- 버튼 하나로 로컬 PC에서 네이버부동산 크롤(로그인 불필요, Playwright). 화면에서:
  - **지역(서울/경기/인천) 복수 · 거래유형(월세/전세/매매) 복수 · 매물 7종 복수**
  - 저장 위치: **로컬 폴더(naver.db, SQLite 누적)** 또는 Supabase(DB URL, 세션모드 자동전환)
  - 테스트(동 3개)·상세정보도 수집(선택)·JSONL export·설정 저장
- 크롤러가 원래 SQLite 방언(`?`, `INSERT OR REPLACE`)이라 공용 어댑터(local_db) 커넥션 재사용, 스키마만 네이버용.
- 검증: 개발 selftest PASS + **로컬 e2e**(역삼동+서초동 오피스텔 월세 2,023건 naver.db 적재) 통과.
- **PyInstaller onefile+windowed 빌드(~55MB)**. Python 3.15 알파라 stdlib `sqlite3`가 동적로드(importlib)
  파일 안에서만 import돼 자동수집 누락 → `--hidden-import sqlite3 --add-binary _sqlite3.pyd/sqlite3.dll`로 해결.
  프로즌 exe `--selftest` PASS. 크로미움은 번들 안 함(PC 설치본 사용, 첫 실행 시 `playwright install chromium`).
- 배포: 바탕화면 `네이버부동산크롤러.exe`로 전달(바이너리라 레포 커밋 안 함, dist_exe/build_exe는 gitignore).
