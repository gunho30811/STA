## 채팅 실시간화 — 오라클 서버 단독 완결 구조 (#277, #278)

- **발견**: 오라클 사이트엔 채팅 자동 폴링이 전혀 안 돌고 있었음(크론이 옛 Vercel/Supabase만
  바라봄). 계정 연결도 컨테이너에 브라우저가 없어 500으로 막혀 있었음(실사용 중 발견).
- **수정**:
  - 계정 연결 500 → Playwright 불가 환경이면 pending_login 큐잉 폴백(#277)
  - Dockerfile에 Playwright 크로미움 내장 — 로그인·재로그인·답장 발송을 서버가 직접 처리
    (삼삼 RTDB·브라우저 로그인 모두 데이터센터 IP에서 동작 확인, 답장 1건 실발송 검증)
  - reauth_needed 계정은 자동 폴링 제외(실패 로그인 무한 반복 방지)
  - cron-poll HTTP 핸들러는 백그라운드 + pg advisory lock(#278)
  - **서버 크론 신설** `/etc/cron.d/rendit-chat-poll`: 매분 `flock -n` + `docker exec
    sta-web-1 python /app/common/chat_poll.py` — HTTP 안 거치고 컨테이너 내부 실행
    (호스트에 8000 미공개라 curl 방식 불가했음). 발화 확인 완료.
- **결과**: 채팅 수신·답장 발송·카톡 알림이 **오라클 서버 단독으로 1~2분 내 준실시간** 동작.
  GH Actions(10분, Supabase) 폴링은 Vercel 백업용으로 그대로 둠.
