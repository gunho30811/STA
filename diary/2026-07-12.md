## gangnam 데이터 계층: 70MB 파일 → DB(naver_listings) 쿼리 전환

- 병목이던 `lab/naver_listings.jsonl`(70MB, 115,645건) 통짜 로드 제거. facets/stats/listings를
  DB SQL로 전환(WHERE/LIMIT/ORDER BY로 필요한 페이지만).
- 필터 SQL화: 타입/지역트리(시·구 분리는 SQL `split_part`/`right`)/방수/보증금·월세·평수 범위/키워드(ILIKE)/업무용.
  역반경은 bbox로 SQL 선필터 후 파이썬 haversine 정밀 판정. 월순수익(net) 정렬·필터는 삼삼 계산이 필요해 파이썬.
  `%s`+`LIKE '%구'` 충돌 회피 위해 `right(sigungu,1)='구'` 사용.
- 근처삼삼(15MB samsam 인덱스)·상세모달(DB)·CSV는 그대로.
- **파리티 검증 통과**: 전체·타입·시도·동·방수·지역 9케이스 total 파일버전과 정확히 일치.
  성능: 기본 목록 첫 요청 159ms(콜드스타트 70MB 로드/1.4초 사라짐), facets 563ms, stats 299ms.
  (월순수익 정렬만 전 매물 계산이라 ~4초 — 원래도 그랬던 드문 경로.)

## 배포 준비 (Vercel) + main 머지

- Vercel은 Git연동 자동배포(main push → api/index.py Flask 서버리스). vercel.json은 pip만 설치하고
  React를 안 빌드 → dist가 없으면 뷰어가 "빌드 없음"으로 깨짐.
- 해결: **`frontend/dist`를 커밋**(gitignore에서 해제). Vercel Python 함수가 lab/data 파일처럼 이 정적
  산출물을 그대로 서빙하므로 별도 빌드스텝 없이 확실히 동작. 총 ~865KB(4뷰어 × index/App js·css).
  `.gitattributes`로 `frontend/dist/** -text`(EOL 변환 방지, 해시-내용 일치). 옛 최상위 dist 잔재 정리.
- 프론트 수정 시: `cd frontend && npm run build` 후 dist 변경분도 함께 커밋해야 배포에 반영됨.
- ⚠️ 배포 전 Vercel 환경변수 `SECRET_KEY` 설정 필요(현재 기본값 dev-insecure면 세션쿠키 위조 위험).
