## 부동산 뷰어 — 방 개수·역 반경·지역 다중선택 필터 (feature/naver-rooms-station-region-filter)

수도권 부동산 뷰어에 세 가지 다중선택 필터를 추가. 데이터는 셋 다 이미 있어서(rooms 컬럼,
매물 lat/lng 99.99%, 역 좌표 CSV) 크롤 없이 export 컬럼 1줄 + 백엔드/프론트만.

- **방 개수(1/2/3/4룸+)**: `rooms` 필드로 칩 다중선택(타입칩과 동일 패턴). 백엔드 `rooms` 파라미터
  반복 → 정수 집합 + '4+'=4개 이상. 실측 1룸 73,871·2룸 24,984·3룸 13,892·4룸+ 2,826.
- **역 반경 검색**: 역 다중선택(datalist 자동완성, 수도권 589역) + 반경(500m/1km/2km/3km) →
  **선택 역들 반경 내 매물 union**. 매물 lat/lng ↔ 역 좌표(data/subway_stations.csv) 하버사인
  (`pipeline/naver/subway.py` 재사용). 예: 홍대입구역+이대역 2km = 3,263건(각 2,542·2,426, 겹침 보정).
  - export에 `lat/lng` 다시 포함(07-05에 파일 경량화하며 뺐던 것). 줄당 ~40B → 66MB→**72.8MB**
    (GitHub 100MB 한도 안전). `export_jsonl.py` COLS + 주석 갱신.
- **지역 다중선택**: 시도→시군→구→동 셀렉트로 좁힌 뒤 **➕지역추가**로 칩 누적(어느 depth든).
  여러 시도/구/동 섞어 union. 백엔드 `region` 파라미터 반복(각 `sido|sigun|gu|dong`, 빈 칸은
  와일드카드). **칩 없이 셀렉트만 선택해도 그대로 적용**(단일선택 기존 동작 유지 — 셀렉트값을
  검색 시 region 하나로 자동 포함, 칩과 중복 제거). 실측 강남구 12,900 + 마포구 2,269 = 15,169.
- 검증: request context로 세 필터 전부 확인(방 합계≈총건, 반경 monotonic 960→2,561→7,124,
  지역 union==sum). 템플릿 JS `node --check` 통과. (API는 auth로 302라 뷰 함수 직접 호출로 검증.)
