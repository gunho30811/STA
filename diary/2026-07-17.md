## 지도 추천 스팟 모달 개선 — 반지하 제외 + 매물 확대 + 총 개수 표시 (feature/reco-more-listings-no-banjiha)

- 지도 '⭐ 추천 스팟만' 모달(`/map`, `web/map_view.py` + `web/samsam_app.py` `/api/recommend`)에 사용자 요청 3건 반영.
- **반지하 제외**: `naver_listings.floor_current`는 정수(1~102)라 반지하 정보가 없고, 반지하는
  `summary`/`summary_tags` 텍스트에 있음(반지하 905 + 반지층 1,151건). 부동산 매칭 쿼리에
  `COALESCE(summary/summary_tags,'') NOT LIKE '%반지하%'/'%반지층%'` 추가(파라미터 바인딩).
- **매물 확대**: 매칭 매물 상위 `LIMIT 3 → 30`(모달이 `overflow-y:auto`·`max-height:78vh`라 스크롤됨).
- **총 개수 표시**: `COUNT(*) OVER()`로 조건 맞는 전체 매물 수(`n_listings`)를 같이 반환 →
  지도 배지("매물N")·모달 헤더("부동산 매물 N건 (월세 싼 순 30건 표시)")에 표기.
- 검증: 로그인 세션 주입 후 `/api/recommend` 실호출 — 200, 스팟 40, 각 동 n_listings(총)+30건 표시,
  표시 매물 중 반지하 0건. 특정 좌표 SQL 대조 428→415건(반지하 13건 제외 확인). map_view는 서버
  렌더 JS라 npm 빌드 불필요.
- 참고: 매칭 반경이 대표좌표 ±1.5km(3km 폭)라 밀집지역은 수천 건. 필요 시 반경 축소/동 일치로 좁힐 여지.

## 추천 스팟 매물 필터 — 보증금 상한 + 건물유형 선택 (feature/reco-deposit-btype-filter)

- 사용자 요청: 추천 스팟 모드에서 ① 보증금을 설정(예산 상한), ② 건물유형(오피스텔·원룸·아파트·연립빌라·
  단독주택·상가주택)을 선택할 수 있게.
- **캐시 리팩터**: 무거운 수요점수 계산(699동×POI, 첫 계산 ~32초)을 `_reco_candidates(conn)` 헬퍼로
  분리해 30분 캐시(보증금·유형과 무관). 매물 매칭(step ④)만 파라미터별로 수행하고 `_RECO['bodies']`에
  `"{유형}|{보증금}"` 키로 캐시 → 보증금/유형 바꿔도 재계산 없이 **0.6초**.
- **파라미터**: `/api/recommend?max_dep=만원&btype=코드`. `btype`은 네이버 코드(OPST/OR/VL/APT/DDDGG/SG),
  없으면 6종 전부. 기존 기본값이 4종(OPST/OR/VL/APT)이라 **단독(DDDGG)·상가(SG) 누락돼 있던 것도 수정**.
  매물 쿼리에 `building_type_code IN (…)`(유형별 플레이스홀더)·`deposit <= %s`(보증금>0일 때) 추가.
- **프론트**(`map_view.py`): 상단 바에 '보증금≤ [ ]만' 입력 추가, `filt.dep`. `loadReco`가 유형 칩·보증금을
  쿼리스트링으로 전달하고 조건 키(`recoKey`)가 바뀌면 재요청(같으면 클라 재사용). 유형 칩 클릭·보증금
  입력 시 추천 모드면 `loadReco()` 재호출.
- 검증: 기본 3,795 → 보증금≤3000만 3,515(캐시 재사용 0.62s)·오피스텔 403·단독+보증금≤1000 219·상가 0.
  py_compile·Jinja 렌더·node JS 문법·엔드투엔드(세션 주입) 통과. map_view는 서버 렌더라 빌드 불필요.
